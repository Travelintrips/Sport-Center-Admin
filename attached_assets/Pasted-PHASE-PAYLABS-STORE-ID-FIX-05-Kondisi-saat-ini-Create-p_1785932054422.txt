PHASE PAYLABS-STORE-ID-FIX-05

Kondisi saat ini:

Create payment gagal dengan error:

storeId: length must be between 6 and 32

Error muncul setelah konfigurasi Paylabs Public Key Sandbox diperbarui.

Tujuan:

Perbaiki validasi dan pembentukan payload storeId tanpa mengubah flow webhook, signature verification, database finalization, atau credential lainnya.

Jangan mengganti merchant ID sandbox.
Jangan mengganti private key sandbox.
Jangan mengganti Paylabs public key sandbox.
Jangan mengubah notifyUrl.
Jangan mengaktifkan production.

PHASE 1 — TRACE SUMBER STORE ID

Cari seluruh referensi:

- storeId
- store_id
- paylabs_store_id
- PAYLABS_STORE_ID

Periksa sumber nilai storeId pada:

- database settings;
- environment variables;
- request body frontend;
- createVAPayment();
- createQRISPayment();
- createH5Payment();
- payload builder.

Laporkan nilai secara aman:

- configured: true/false
- trimmedLength
- source: database/environment/default

Jangan menampilkan nilai Store ID penuh di log.

Pastikan frontend tidak boleh menentukan storeId sendiri.

PHASE 2 — ATURAN STORE ID

Terapkan aturan:

1. Trim whitespace.
2. Jika kosong setelah trim:
   - anggap tidak dikonfigurasi;
   - jangan sertakan properti storeId dalam payload Paylabs.
3. Jika tersedia:
   - panjang minimum 6;
   - panjang maksimum 32.
4. Jika panjang tidak valid:
   - tolak penyimpanan di admin settings;
   - tampilkan error yang jelas;
   - jangan menunggu sampai request Paylabs gagal.
5. Jangan memakai nilai default pendek seperti:
   SC
   SIT
   DEV
   001
6. Jangan membuat Store ID buatan tanpa konfirmasi Paylabs.

Gunakan helper terpusat, misalnya:

function normalizeOptionalPaylabsStoreId(value?: string | null): string | undefined {
  const normalized = value?.trim();

  if (!normalized) {
    return undefined;
  }

  if (normalized.length < 6 || normalized.length > 32) {
    throw new Error(
      "Paylabs Store ID must contain between 6 and 32 characters"
    );
  }

  return normalized;
}

PHASE 3 — PAYLOAD BUILDER

Jangan membuat payload seperti:

{
  storeId: storeId || ""
}

Jangan membuat:

{
  storeId: undefined
}

jika serializer atau validator tetap mempertahankan properti tersebut.

Gunakan conditional spread:

const normalizedStoreId =
  normalizeOptionalPaylabsStoreId(config.storeId);

const payload = {
  merchantId,
  merchantTradeNo,
  amount,
  notifyUrl,
  ...(
    normalizedStoreId
      ? { storeId: normalizedStoreId }
      : {}
  ),
};

Pastikan JSON.stringify(payload) benar-benar tidak memiliki key storeId jika tidak dikonfigurasi.

Terapkan konsisten pada:

- VA create;
- QRIS create;
- H5 create link;
- inquiry hanya jika endpoint memang memerlukan storeId.
