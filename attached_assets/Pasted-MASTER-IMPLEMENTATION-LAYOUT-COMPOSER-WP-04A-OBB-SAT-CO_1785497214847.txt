==================================================
OWNER DECISIONS — AUTHORITATIVE
==================================================

Use these decisions exactly.

1. UNIT CONVENTION

Layout Composer internal geometry uses pixels.

Any cm/mm conversion must occur only at input/output boundaries.

Do not mix pixels and physical units inside collision algorithms.

2. PUSH VECTOR CONVENTION

Push vector means the displacement applied to object A
to move object A out of object B:

resolvedPosition = originalPosition + pushVector

This convention must be consistent across:

- adapters
- collision resolver
- APIs
- tests

3. BROAD PHASE

Use canonical AABB overlap as broad-phase filtering.

Only run OBB/SAT narrow-phase when AABBs overlap.

Do not run SAT against every possible pair unnecessarily.

4. PERFORMANCE BUDGET

Support:

- up to 500 elements
- up to 100 collision-resolution iterations
- finite deterministic execution
- explicit iteration caps
- no unbounded recursion or loops

Target:

standard layout collision processing under 1 second
in the repository test environment.

Performance benchmark results must be reported honestly.

5. CLEARANCE

Clearance expands the collision envelope only.

It must not change visual width, height, or rendering dimensions.

Clearance must be handled consistently by broad phase and narrow phase.

6. BACKWARD COMPATIBILITY

Do not remove overlapExtent or break existing consumers.

Introduce a new SAT/manifold result structure.

Provide compatibility mapping from the new result to the legacy overlapExtent format.

Mark legacy overlapExtent as deprecated where appropriate.

Do not remove it in WP-04A.
