## 2. VALIDASI PAYLABS

Verifikasi final behavior:

### Success baru

Harus menghasilkan:

`payment_method = QRIS`

`payment_provider = paylabs`

`merchant_trade_no`

`provider_trade_no / paylabs_trade_no`

`provider_reference`

`paid_at`

### Duplicate webhook

Harus:

* tidak membuat duplicate payment;
* tidak mengubah `paid_at`;
* tetap idempotent.

### Booking terminal

Jika booking sudah:

`cancelled`

`expired`

`rejected`

`refunded`

webhook success tidak boleh diam-diam mengubah menjadi `confirmed`.

Harus menghasilkan behavior manual-review/safe handling yang sudah dirancang.

Tambahkan/fix test jika belum ada.

## 3. VALIDASI QRIS MANUAL

Pastikan transaksi QRIS manual baru:

* wajib mempunyai `payment_provider`;
* hanya menerima provider allowed;
* tidak otomatis dianggap Mandiri jika caller tidak mengirim provider;
* non-QRIS tetap backward-compatible.

Jika UI tertentu memang eksklusif QRIS Mandiri Direct, caller boleh mengirim:

`payment_provider = mandiri_direct`

secara explicit.

Jangan infer provider dari:

* payment method QRIS;
* screenshot;
* amount.
