============================================================
12. RESCHEDULE — HIGH PRIORITY
============================================================

Tutup HIGH-RISK GAP yang ditemukan audit.

Current problem:

REQUEST RESCHEDULE memeriksa blocked schedule,

tetapi APPROVAL TRANSACTION hanya memeriksa booking aktif.

Ini harus diperbaiki.

Approval wajib melakukan conflict validation
DI DALAM TRANSACTION yang sama dengan mutation.

Pattern:

BEGIN
→ lock/check target facility/time
→ check all conflicting bookings
→ check event
→ check recurring occurrence
→ check replacement occurrence
→ validate request
→ update booking/reschedule
→ write history
COMMIT

Jika conflict ditemukan:

ROLLBACK

Tidak boleh:

check availability
→ beberapa saat kemudian update

karena itu race condition.
