## PHASE 4 — SECRET MANAGER DESIGN

Hapus rencana menggunakan:

gcloud app deploy ... --set-env-vars="SECRET=..."

Jangan mengirim secret melalui command line.

Siapkan desain Google Secret Manager.

Gunakan nama secret production, misalnya:

- sport-center-prod-supabase-database-url
- sport-center-prod-session-secret
- sport-center-prod-fonnte-token

Jangan membuat nilai secret dan jangan meminta nilainya.

Audit:

- apakah aplikasi sudah punya secret loader;
- apakah loader mendukung Google Secret Manager;
- apakah menggunakan Application Default Credentials;
- runtime service account apa yang direkomendasikan;
- IAM role minimum.

Gunakan role minimum:

roles/secretmanager.secretAccessor

Jangan memberikan runtime secret ke Cloud Build jika build tidak memerlukannya.

## PHASE 5 — REPLIT OBJECT STORAGE COMPATIBILITY

Audit seluruh penggunaan:

- @replit/object-storage
- replitStorage.ts

Laporkan:

- fitur yang terdampak;
- route yang memakai;
- apakah dipanggil saat startup;
- apakah dapat menyebabkan crash;
- data apa yang disimpan.

Karena production menggunakan Supabase, prioritaskan Supabase Storage.

Buat storage abstraction:

- Supabase Storage untuk production GAE;
- Replit storage hanya untuk development bila masih diperlukan;
- production tidak boleh mengakses 127.0.0.1:1106;
- tidak ada silent fallback;
- error handling jelas.

Jangan migrasikan file lama tanpa persetujuan.

Tambahkan test bahwa production mode tidak pernah mencoba memakai Replit sidecar.
