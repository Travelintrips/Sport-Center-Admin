SPORT CENTER / CST SUPER APP

JANGAN BERTANYA KONFIRMASI.
KERJAKAN SEMUA BAGIAN YANG AMAN SECARA OTOMATIS.

KONDISI:
Production-data audit BLOCKED karena production database connection tidak tersedia.

Tidak boleh menggunakan DEV sebagai pengganti PROD.

Audit sebelumnya juga mengindikasikan tindak lanjut:
- kemungkinan credential production pernah terekspos
- production Secret Manager/IAM belum dapat diverifikasi dari workspace aktif

TARGET:
1. Audit exposure credential secara menyeluruh.
2. Hilangkan credential production dari source/config yang tidak semestinya.
3. Pastikan architecture menggunakan Google Cloud Secret Manager sebagai source of truth.
4. Pastikan Replit hanya menggunakan bootstrap/access secret yang memang diperlukan.
5. Jangan melakukan rotasi credential production secara langsung jika membutuhkan akses owner/external production.
6. Setelah remediation code/config selesai, lakukan seluruh verification yang dapat dilakukan dari DEV.

PHASE 3 — CURRENT CONFIG CLEANUP
==================================================

Jika credential production ditemukan dalam:

- source code
- tracked config
- documentation
- example file
- test fixture
- committed .env

hapus/replace dengan placeholder NON-SECRET jika aman.

Contoh:

SUPABASE_DATABASE_URL=<provided-at-runtime>

JANGAN mengganti dengan credential baru.

JANGAN memasukkan credential ke source code.

==================================================
PHASE 4 — SECRET ARCHITECTURE
==================================================

Gunakan architecture:

Google Cloud Secret Manager
        ↓
production runtime identity
        ↓
official secret loader
        ↓
application

Replit Secrets hanya untuk bootstrap/access secret yang memang diperlukan untuk mengakses Secret Manager atau tooling.

Jangan menjadikan Replit Secrets sebagai permanent source of truth untuk application secrets.

Audit existing:

- Secret Manager loader
- bootstrap JSON
- GCP project
- service account
- IAM
- secret names
- runtime identity
- environment resolver

Jangan menampilkan secret values.

==================================================
PHASE 5 — FAIL-CLOSED
==================================================

Pastikan production application:

Jika production secret tidak dapat dibaca:
→ fail closed

Jangan fallback ke:

- DEV database
- local database
- hardcoded credential
- stale database URL
- arbitrary DATABASE_URL
- anonymous database access

Pastikan environment separation:

DEV → DEV
PROD → PROD

Jangan izinkan:

PROD → DEV fallback
atau
DEV → PROD accidental connection.

==================================================
PHASE 6 — ENVIRONMENT GUARD
==================================================

Audit seluruh code yang menentukan database target.

Pastikan production detection tidak hanya berdasarkan:

NODE_ENV

Gunakan architecture existing yang dapat membedakan:

- development
- production
- test

Pastikan:

development cannot accidentally connect production
production cannot silently fall back development

Jika environment mismatch:
→ fail closed.
