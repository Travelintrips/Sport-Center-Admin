Tolong lakukan audit **read-only** terhadap credential Google Secret Manager yang benar-benar dipakai oleh **Replit production deployment**.

Konteks saat ini:

* App Engine → Versions kosong.
* Jadi production bukan berjalan di App Engine.
* Production kemungkinan berjalan sebagai Replit Deployment.
* DEV sudah berhasil mengakses shared secret `sport-center`.
* Production masih gagal dengan:

`403 Permission 'secretmanager.versions.access' denied`

* Di Google Cloud, service account berikut sudah memiliki role `Secret Manager Secret Accessor` pada secret `sport-center`:

`sport-center@sport-center-506306.iam.gserviceaccount.com`

Karena itu, kemungkinan production deployment memakai bootstrap credential yang berbeda/lama.

## Tujuan audit

Pastikan identity yang benar-benar dipakai oleh production deployment sama dengan identity yang sudah diberi IAM access.

Jangan mengubah data production.

Jangan mengubah IAM.

Jangan rotate key.

Jangan mencetak secret payload.

Jangan mencetak private key.

## Variable yang harus diperiksa di production deployment

Periksa keberadaan dan nilai non-sensitive dari:

`GCP_SECRET_MANAGER_BOOTSTRAP_JSON`

`GCP_PROJECT_ID`

`GCP_SECRET_ID`

`APP_ENV`

atau `NODE_ENV` jika itu source of truth runtime.

Expected:

`GCP_PROJECT_ID = sport-center-506306`

`GCP_SECRET_ID = sport-center`

`APP_ENV = production`

## Audit bootstrap JSON

Parse:

`GCP_SECRET_MANAGER_BOOTSTRAP_JSON`

Tetapi hanya laporkan field berikut:

`type`

`project_id`

`client_email`

`private_key_id`

`token_uri`

Jangan print:

`private_key`

Jangan print seluruh JSON.

Expected identity:

`project_id = sport-center-506306`

`client_email = sport-center@sport-center-506306.iam.gserviceaccount.com`

Expected key ID saat ini:

`53291648471428af530eee2a9b4bb53dd9095dcb`

Jika `client_email` atau `private_key_id` berbeda, laporkan sebagai mismatch.

## Sangat penting: production deployment vs workspace

Jangan hanya membaca environment workspace DEV.

Audit harus memastikan nilai yang benar-benar tersedia di **production deployment runtime**.

Pisahkan hasil:

`Workspace secret`

dari:

`Production deployment secret`

Jika tool/Replit API tidak memungkinkan membaca metadata production deployment secara langsung, laporkan itu dengan jelas dan jangan menganggap workspace = production.

`Shared secret access: PASS`

## Jika masih 403

Jika error masih:

`403 Permission 'secretmanager.versions.access' denied`

laporkan identity yang dipakai request:

`client_email`

dan bandingkan dengan:

`sport-center@sport-center-506306.iam.gserviceaccount.com`

Jika berbeda, root cause adalah production memakai credential berbeda.

Jika sama, periksa:

* project target benar
* secret target benar
* credential key masih valid
* request benar-benar dibuat menggunakan bootstrap credential tersebut, bukan Application Default Credentials atau credential lain

## Periksa inisialisasi SDK

Cari apakah production client dibuat seperti:

`new SecretManagerServiceClient()`

tanpa explicit credentials.

Jika iya, periksa apakah runtime malah memakai Application Default Credentials.

Untuk desain ini, pastikan client benar-benar memakai bootstrap credential jika itu memang source of truth.

Contoh konseptual:

```js
new SecretManagerServiceClient({
  projectId: bootstrap.project_id,
  credentials: {
    client_email: bootstrap.client_email,
    private_key: bootstrap.private_key
  }
});
```

Sesuaikan dengan library/version yang digunakan.

Jangan refactor jika tidak diperlukan.
