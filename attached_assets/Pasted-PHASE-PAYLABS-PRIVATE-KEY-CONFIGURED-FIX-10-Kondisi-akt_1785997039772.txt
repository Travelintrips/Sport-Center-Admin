PHASE PAYLABS-PRIVATE-KEY-CONFIGURED-FIX-10

Kondisi aktual:

- Paylabs Public Key Sandbox sudah Configured.
- Merchant ID Sandbox sudah terisi.
- Merchant Private Key Sandbox sudah ditempel dan disimpan oleh user.
- Setelah refresh, badge tetap Not configured.
- Jangan mengubah Paylabs Public Key, Merchant ID, Store ID, webhook, notifyUrl, atau payment flow.

Tujuan:

Pastikan Merchant Private Key Sandbox:

1. benar-benar terkirim dari frontend;
2. tervalidasi sebagai RSA private key;
3. tersimpan ke database pada canonical key yang benar;
4. dibaca kembali oleh GET settings;
5. menghasilkan sandboxPrivateKeyConfigured: true;
6. tetap Configured setelah refresh dan restart.

PHASE 1 — TRACE FRONTEND PATCH

Reproduksi:

1. Buka /admin/paylabs.
2. Klik Set Merchant Private Key.
3. Tempel private key sandbox.
4. Klik Simpan Perubahan.

Trace request PATCH.

Laporkan tanpa menampilkan key:

- endpoint;
- field name yang dikirim;
- apakah field ada di payload;
- panjang input;
- detected PEM type;
- apakah editor private key sedang open;
- apakah payload dibentuk sebelum editor ditutup;
- response HTTP;
- response body aman.

Pastikan field yang dikirim konsisten, misalnya:

sandboxPrivateKey

Jangan memakai variasi berbeda antara frontend dan backend seperti:

merchantPrivateKeySandbox
paylabsPrivateKeySandbox
sandboxMerchantPrivateKey

Gunakan satu nama kontrak saja.

PHASE 2 — VERIFY BACKEND RECEIVES FIELD

Pada PATCH paylabs settings, log metadata aman:

[paylabs-settings] sandbox private key update
{
  received: true,
  inputLength: <number>,
  detectedType: "PRIVATE KEY" | "RSA PRIVATE KEY" | "UNKNOWN",
  normalizedLength: <number>,
  createPrivateKeyValid: true | false
}

Jangan log isi key.

Jika field tidak diterima, perbaiki frontend payload.

Jika diterima tetapi invalid, return HTTP 422 dengan pesan:

"Merchant Private Key Sandbox tidak valid."

Jangan menampilkan toast sukses.

PHASE 3 — ALIGN CANONICAL DB KEY

Gunakan satu konstanta:

const PAYLABS_SETTINGS_KEYS = {
  sandboxPrivateKey: "paylabs_private_key_sandbox",
  sandboxPublicKey: "paylabs_public_key_sandbox",
  sandboxMerchantId: "paylabs_merchant_id_sandbox",
};

Pastikan:

- PATCH menulis ke paylabs_private_key_sandbox;
- GET membaca paylabs_private_key_sandbox;
- config resolver signing membaca paylabs_private_key_sandbox;
- tidak ada key alternatif sebagai source of truth.

Cari seluruh variasi:

- paylabs_private_key_sandbox
- paylabs_sandbox_private_key
- sandbox_private_key
- private_key_sandbox
- merchant_private_key_sandbox

Laporkan jika ada mismatch.

PHASE 4 — VERIFY DATABASE DIRECTLY

Setelah save, query database secara langsung.

Laporkan hanya:

- key exists;
- nonEmpty;
- storedLength;
- detected PEM type;
- crypto.createPrivateKey valid;
- updatedAt.

Jangan menampilkan nilai.

Expected:

key = paylabs_private_key_sandbox
exists = true
nonEmpty = true
crypto.createPrivateKey valid = true

Jika row tidak ada, perbaiki upsert.

Jika row ada tetapi invalid, jangan tandai Configured.

PHASE 5 — CONFIGURED BOOLEAN

GET /api/paylabs/settings harus menghitung:

sandboxPrivateKeyConfigured =
  storedValue exists
  AND crypto.createPrivateKey(storedValue) succeeds

Jangan hanya memeriksa:

storedValue.length > 0

karena nilai masked/corrupt dapat terlihat non-empty.

Jangan hanya membaca environment variable.

Urutan resolver sandbox:

1. DB paylabs_private_key_sandbox jika valid
2. PAYLABS_PRIVATE_KEY_SANDBOX jika valid
3. fallback PAYLABS_PRIVATE_KEY hanya jika kebijakan memang mengizinkan
4. jika tidak ada valid key → false

Laporkan source yang dipakai:

database
environment
none

6. lakukan hard refresh;
7. badge tetap Configured;
8. restart API;
9. badge tetap Configured.

Jangan mengubah badge menjadi Configured secara optimistik sebelum GET mengonfirmasi.

PHASE 7 — VALIDATE PRIVATE KEY FORMAT

Terima hanya:

-----BEGIN PRIVATE KEY-----
...
-----END PRIVATE KEY-----

atau:

-----BEGIN RSA PRIVATE KEY-----
...
-----END RSA PRIVATE KEY-----

Normalize:

- literal \n → newline;
- CRLF → LF;
- trim outer whitespace;
- preserve header type.

Lalu validasi dengan:

crypto.createPrivateKey()

Jika gagal:

- jangan simpan;
- pertahankan nilai lama;
- HTTP 422;
- tampilkan pesan konfigurasi invalid.
