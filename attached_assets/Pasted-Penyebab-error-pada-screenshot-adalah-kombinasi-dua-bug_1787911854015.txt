Backend masih langsung melakukan INSERT

Proses “Tutup rule lama & buat baru” mendeteksi overlap di UI.
Namun handler backend tetap mencoba membuat row baru tanpa menutup atau mengganti row lama secara atomik.
Rule baru memakai tanggal mulai yang sama dengan Rule #4

Rule #4 sudah mulai pada 2026-01-01.
Rule baru juga memakai effective_from = 2026-01-01.
Database memiliki unique constraint untuk kombinasi:
company_id + provider_code + bank_account_id + effective_from

Akibatnya insert ditolak sebagai data duplikat.

Selain itu, menutup Rule #4 dengan tanggal 2025-12-31 juga tidak valid karena Rule #4 sendiri mulai 2026-01-01. Periode tersebut akan menjadi terbalik.

Perilaku yang benar seharusnya:

Jika tanggal mulai baru sama dengan rule lama: update/revisi row lama, bukan insert duplikat.
Jika tanggal mulai baru setelah rule lama: ubah effective_until rule lama menjadi satu hari sebelum rule baru.
Jika rule lama mulai setelah atau sama dengan rule baru: tandai sebagai superseded/nonaktif tanpa membuat periode tanggal invalid.
Seluruh proses harus dilakukan dalam satu transaksi dengan row lock dan audit log.
