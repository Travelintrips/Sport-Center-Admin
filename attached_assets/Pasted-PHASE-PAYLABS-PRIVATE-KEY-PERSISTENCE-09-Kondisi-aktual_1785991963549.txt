PHASE PAYLABS-PRIVATE-KEY-PERSISTENCE-09

Kondisi aktual:

1. Paylabs Public Key Sandbox sudah berhasil disimpan.
2. Badge menunjukkan Configured.
3. Create payment masih gagal dengan:

RSA signing failed
DECODER routines::unsupported

4. Merchant Private Key Sandbox ditampilkan pada textarea sebagai deretan karakter masker/titik.
5. Kemungkinan besar masked value atau placeholder terkirim kembali saat Simpan Perubahan dan menimpa private key asli.

Tujuan:

Pastikan Merchant Private Key Sandbox:

- tidak pernah dikembalikan ke frontend;
- tidak pernah ditampilkan sebagai masked textarea value;
- tidak tertimpa saat user hanya mengganti public key atau settings lain;
- hanya diperbarui ketika user secara eksplisit memasukkan private key baru;
- tervalidasi dengan crypto.createPrivateKey() sebelum disimpan;
- dapat digunakan untuk RSA signing request Paylabs sandbox.

Jangan mengubah Paylabs Public Key Sandbox.
Jangan mengubah Merchant ID Sandbox.
Jangan mengubah Store ID.
Jangan mengubah notifyUrl atau webhook flow.
Jangan masuk production.

PHASE 1 — TRACE NILAI PRIVATE KEY SAAT INI

Audit sumber Merchant Private Key Sandbox:

- DB key paylabs_private_key_sandbox
- env PAYLABS_PRIVATE_KEY_SANDBOX
- fallback PAYLABS_PRIVATE_KEY
- admin PATCH payload
- config resolver

Laporkan hanya metadata:

- source
- configured true/false
- stored length
- detected PEM type
- begins with PRIVATE KEY / RSA PRIVATE KEY / UNKNOWN
- contains real newlines true/false
- contains literal \n true/false
- contains only mask characters true/false
- crypto.createPrivateKey succeeds true/false

Jangan menampilkan isi private key.

Cari apakah database sekarang berisi:

- bullet characters
- asterisks
- masked placeholder
- string "configured"
- string "[REDACTED]"

Jika iya, konfirmasi root cause:
MASKED VALUE OVERWROTE PRIVATE KEY.

Hapus field seperti:

Frontend harus menampilkan:

Configured
[Ganti Merchant Private Key]

atau:

Not configured
[Set Merchant Private Key]

Tidak boleh menampilkan textarea berisi deretan titik secara default.

PHASE 4 — FIX BACKEND PATCH SEMANTICS

Pada PATCH settings:

- jika field sandboxPrivateKey tidak ada:
  pertahankan private key lama;
- jika field ada tetapi empty:
  jangan menimpa key lama;
- jika field berisi masker atau placeholder:
  return HTTP 422;
- jika field berisi key baru:
  normalize dan validate sebelum upsert.

Tolak nilai berikut:

/^[•*]+$/
"Configured"
"[REDACTED]"
"********"
empty string

Jangan gunakan:

sandboxPrivateKey =
  body.sandboxPrivateKey || ""

Jangan menggunakan object spread yang selalu memasukkan key kosong.

PHASE 5 — PRIVATE KEY NORMALIZATION

Buat atau gunakan helper:

normalizePaylabsPrivateKey()

Mendukung:

-----BEGIN PRIVATE KEY-----
PKCS#8
-----END PRIVATE KEY-----

dan:

-----BEGIN RSA PRIVATE KEY-----
PKCS#1
-----END RSA PRIVATE KEY-----

Helper harus:

- trim outer whitespace;
- ubah literal \\n menjadi newline asli;
- ubah CRLF ke LF;
- preserve header type;
- jangan mengubah key menjadi public key;
- jangan membungkus raw base64 secara asal;
- jangan menghapus karakter base64.

Setelah normalisasi, wajib:

crypto.createPrivateKey(normalizedKey)

Jika gagal:

- jangan simpan;
- pertahankan key lama;
- return HTTP 422;
- frontend tampilkan pesan:
  "Merchant Private Key Sandbox tidak valid."
